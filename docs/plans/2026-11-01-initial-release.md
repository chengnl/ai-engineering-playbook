# AI Engineering Playbook v0.1 实施计划

目标：交付可迁移的中文AI研发规范、分级轻量SDD流程、项目接入模板和无需第三方依赖的验证工具。
架构：通用规则、技术适配、执行流程、模板、检查工具分离；模板复制到目标仓库，固定采用版本；不包含任何业务源码、生产配置、凭据或真实数据。
技术：Markdown、Python 3.10+标准库、Git。本文为实施计划，不代表已验证或已发布。

## 任务与验证

- [x] T1：建立规范入口、使用指南与项目适配约定；人工核对新项目/已有项目接入和迁移步骤。
- [x] T2：提炼Java、前端、数据库、测试、安全与协作规范；每条区分必须、建议和按需，提供例外机制。
- [x] T3：建立简化/标准/增强SDD流程，模板覆盖规格、设计、任务、验收、发布和知识维护。
- [x] T4：编写初始化工具；测试新目录、已有工程安全接入、拒绝覆盖/符号链接、版本记录、无网络副作用和失败清理。
- [x] T5：编写文档/追踪检查及本地命令入口；覆盖断链、重复/未知需求关联、未配置检查不能假通过、非零/超时结果。
- [x] T6：在临时新工程完成接入冒烟与全部离线测试；清理临时目录，记录真实证据。
- [ ] T7：检查Git内容和文档一致性，提交并推送至用户指定GitHub仓库。保留现有业务工程的工作区改动。

## 边界

此仓库不生成可上线业务应用，不自带数据库/浏览器/生产测试环境；初始化的是研发治理骨架。工程技术栈和业务代码由AI在用户确认适用方案后建立。自动检查只覆盖明确实现的规则，不能证明业务正确、安全或全规范符合。无CI工作流默认部署，不自动提交、推送或调用模型。
