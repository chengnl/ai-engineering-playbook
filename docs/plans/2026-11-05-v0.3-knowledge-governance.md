# v0.3 文档治理与方案审视实施计划

目标：将现行知识整合维护、历史与实验隔离、合并前清理、阶段性人工复查和业务/产品/技术审视接入规范、模板、流程及初始化。

架构：通用规则集中standards；项目AGENTS只作入口，规格与验收模板承接实际记录。新项目按需使用docs分类，已有项目不自动迁移。Python标准库初始化继续无覆盖、无外部执行，项目/追踪schema保持2。

## 联合审视与取舍

业务：沉淀研发约束而非复制某应用角色/服务器。产品：知识入口保持短，模块、操作、实验和历史可区分，简单变更可合并材料。技术：规则、结构检查和人工语义评审分开；初始化安全边界和既有项目兼容优先，不增加语义评分器或外部服务。

推荐增加独立documentation规范，默认适用于新项目；已有v0.2包显式升级，保留原docs。不能只新增一份口号文档或把培训项目八份根文档强制给所有技术栈。

## 任务与验证

1. 更新collaboration、SDD/开发/集成流程、AGENTS/规格/ADR/验收/发布模板；加入目录及阶段复查规范。
2. 新增docs目录入口模板；bootstrap仅在新docs目录生成分类骨架，已有目录/知识字节不变，新建入口仅引用存在的文件。
3. 回归新项目索引/规范复制、已有docs完整保留、缺入口兼容、docs异常类型/符号链接拒绝、部分写入失败清理及离线完整教学示例。
4. 更新版本0.3.0、接入/维护/检查边界与实际验收，执行check.py及全部unittest；不自动提交、推送、安装到业务工程或调用业务资源。

## 完成条件

新项目拿到目录和审视/维护约束；老项目不被自动移动或覆盖；链接和离线测试有真实证据。人工审视和阶段性复查不是新自动门禁，运行证据以本次验收为准。


验收期间补充：既有中断用例暴露进程组退出探测暂时PermissionError会提前逃出清理链。限定修复仅在原grace内等待可证实退出，权限拒绝不等于退出；持续拒绝记录关闭未知且整体失败，仍尝试已声明清理及残留hook，新增正反回归，不修改授权或延长总期限。

实施结果见[实际验收](../acceptance/2026-11-05-v0.3.md)，不将计划本身当作运行证据。
