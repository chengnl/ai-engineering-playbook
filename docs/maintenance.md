# 规范版本、适配与维护

采用时记录VERSION和Git提交/tag；manifest.json保留初始复制文件摘要，不是自动更新器。目标项目可按业务适配规则，必须留下例外的规则编号、原因、范围、风险、补偿和复查条件。

规范升级不静默覆盖项目。先读CHANGELOG，对比原版本、本地适配和新版本，合并变更并更新采用版本/摘要与例外，执行项目适用检查，更新项目知识。v0.1工具没有自动升级/三方合并能力；重跑bootstrap会拒绝已有包。

每次规范迭代同步README、索引、模板、工具和适用测试。规则编号避免无理由重用；改变强制程度、格式或工具行为写清兼容影响。重大选择保存技术决策或日期方案。

新项目试用不能证明所有技术栈可用。应先在第二个实际项目验证，再决定增加语言适配、自动架构检查、CI集成或AI Skill。不要复制来源项目的生产路径、默认角色、历史测试数量和临时CI决定。
