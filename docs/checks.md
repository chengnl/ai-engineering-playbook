# 检查工具：能力、边界与退出码

## bootstrap

只使用本地规范源，复制固定版本到目标`.engineering`，生成项目说明和入口。默认拒绝已有AGENTS；`--no-agent-entry`生成待合并片段。保留已有README/知识入口，不覆盖既有治理包，拒绝符号链接目标。创建时使用独占锁和独占文件写入，普通异常/中断尽力回滚本次文件；进程被强杀或断电后需人工检查部分文件，不能承诺跨文件原子事务。

成功退出0但项目仍needs-adaptation；失败退出2。无安装依赖、git操作、业务源码生成、CI配置、网络或模型调用。

## check

- Markdown：检查简单内联相对链接指向的本地文件/目录是否存在且未越出扫描根，忽略常见运行/缓存目录及代码围栏。
- 追踪JSON：schema、ID唯一性、需求覆盖、未知关联、状态与本地证据路径；completed要求任务done及所有验收passed并有存在的证据文件。
- 不解析所有Markdown语法/引用式链接，不验证锚点、外部URL、证据内容真实性、业务语义或测试覆盖质量。未要求检查的范围不执行。无自动源码架构规则或安全扫描器。

成功0、发现问题1、参数缺失2。规格ready不等于用户批准；completed标签仍由责任人结合事实判定，工具不能替代审批或实际测试。

## verify

从项目`.engineering/project.json`读取status与checks；仅ready且所选组全部有合法命令时执行。检查项包括argv字符串数组、timeout_seconds（1..7200）及purpose。`--group all`执行配置内全部组，任一组未配置即预检失败，执行前不运行任何命令。

使用argv直接启动、不经shell插值，工作目录为项目目录；但用户显式配置shell/python等本身仍可执行任意动作，禁止将此当命令安全过滤。命令stdout/stderr直接继承，项目须自己脱敏。非零立即停止，超时/中断在POSIX终止本地进程组并等待回收；Windows仅终止直接子进程，不承诺全部后代回收。终止本地进程不能撤销远端已执行副作用。

成功0、命令非零1、配置/启动问题2、超时/执行中断124。PASS只说明这些命令退出零，不证明其测试有效、全规范符合或生产安全。
