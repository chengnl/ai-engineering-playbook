# 如何使用模板建立和开发下一个工程

“让AI学习”是每次执行前读取仓库规则和当前规格，不是把规则永久训练进模型。入口可由不同AI客户端适配，规范文件与证据才是可审查依据。

## 新项目

1. 克隆本规范仓库，选择Git版本/tag并记录，先阅读README及适用规则。
2. 运行`python3 tools/bootstrap.py --destination ../my-project --name my-project`。目标目录不存在则创建；已有普通目录可接入，但绝不覆盖同名文件或既有治理包。docs尚不存在时生成按职责分类的README骨架；没有虚构的API/数据库/业务正文，按实际项目裁剪。
3. 在目标工程填写`.engineering/project.json`：业务/角色/数据边界、技术栈、知识入口、测试资源清理、Git/CI/环境授权和检查命令。不要填写任何凭据。
4. 向AI描述业务目标，要求先读AGENTS.md和规范，先审视业务/产品/技术，给出推荐、主要取舍、验证标准、适用项和例外。明确关键取舍后建立业务源码、构建/测试、数据库迁移和知识文档。模板不会替你选择或安装框架。
5. 绑定真实的本地测试命令，拆分离线/数据库/浏览器/付费模型范围。补适用规范、非生产环境和source_paths，各检查组明确命令/资源清理或不适用理由；核对安全边界后将status改为ready并运行check.py --project。
6. 按轻量SDD执行功能迭代，核对需求、任务和验收；按风险测试、资源清理、知识同步，再按授权集成或发布。

## 已有项目

先盘点代码和现行文档，保留原CI/分支/构建与权限约定。若已有AGENTS.md，使用`--no-agent-entry`，将生成的`.engineering/AGENTS.snippet.md`由人/AI审阅后合入原入口；不覆盖原规则。已有README及整个docs保持原样，需人工补入口和分类；已有docs无README时仅创建不假设分类已存在的入口，不搬动其他文件。

不要为了接入规范全仓重构或重写历史规格。schema 1升级参照维护指南，不能只改版本号或旧证据。先选一个真实变更试用，记录存量偏差与例外，再逐模块治理。初始化不更新已有`.engineering`，重跑会拒绝；升级见[维护指南](maintenance.md)。

## 可以直接给AI的启动指令

> 读取本项目AGENTS.md、.engineering/README.md、project.json、适用规范与现行知识。先审视业务目标/规则/例外/衡量、产品流程/交互/状态/错误恢复、技术架构/兼容/成本/可靠性/测试/回退，再给综合推荐、取舍、验证标准和适用规则/例外。已授权范围内持续推进；关键业务/数据/权限边界不清楚时先澄清。建立业务工程后绑定实际测试命令，执行验证并同步知识；不擅自发布、推送、删除真实数据或调用付费服务。

## 每轮迭代指令

> 按本项目采用的规范版本处理本次变更。先判断简化/标准/增强SDD，明确范围、保留行为、需求与验收；标准/增强建立需求—任务—证据关联。按风险实施和验证，需求变化及时同步规格。复查实际diff工程符合性，整合现行知识和分类索引，合并前清理本轮重复/矛盾/过时描述和失效引用；历史记录保留替代关系。发布/里程碑/方案替代做阶段性人工知识复查，报告实际结果、跳过、遗留与复查条件。

## 交付前必须理解

初始化成功≠业务应用完成；工具检查通过≠全部需求符合；AI自查≠独立人工审批；本地通过≠远端CI通过；保存配置≠发布生效；推送代码≠部署服务。权限取决于当前用户授权和目标环境，不由模板授予。

## 完整教学与技术适配

先运行[完整教学闭环](../examples/complete/README.md)，观察真实失败回归、修复、证据生成及completed追踪；再选[技术栈适配](../adapters/README.md)绑定实际Java/前端/数据库检查。教学用例不代表目标应用已验证。
