# 提交、合并与发布

## 提交和合并前

1. 核对当前分支、工作区与差异归属，排除其他任务/用户改动；不盲目git add全部。
2. 核对变更规格、任务和验收，按风险执行检查并记录本次证据。失败不得靠忽略退出码通过。
3. 按[文档规范](../standards/documentation.md)整合受影响现行知识、根README及分类索引，清理本轮重复、矛盾、过时环境/功能、旧API/路径及失效链接；保留历史事实和替代关系，不把方案当上线。复查实际diff的工程符合性，记录未覆盖项与例外。
4. 扫描暂存内容和构建产物，排除凭据、真实数据、备份、运行日志和生成大文件。
5. 基于当前用户授权执行提交/推送/合并；需要备份tag、MR或独立评审按项目约定，不强制所有项目同一Git策略。
6. 核对远端提交与本地结果，说明未提交/未推送/未部署状态。规范包不读取远端权限设置，不能声称已启用保护分支/强制审批。

## 发布前后

- 明确目标环境、Git版本、产物摘要、配置/数据库版本、维护窗口、健康与回退条件。
- 数据库与应用部署采用项目受控工具；备份可读校验不等于恢复演练。
- 迁移、权限、程序切换、健康和真实入口按适用范围验证，禁止跨环境误操作。
- 发布失败或中断保持现场和恢复依据；未知结果先核实，不盲重放副作用。
- 记录完成的环境、验证结果、备份位置和回退限制，不向仓库写入密钥或客户数据。

## 阶段性知识复查

发布完成、里程碑结束或方案替代时，人工复查受影响总览/模块/运维/指南及历史替代链接，记录触发、基线、范围、发现/处理、遗留风险和复查条件。可合并在发布/验收记录，复杂时用[知识复查模板](../templates/knowledge-audit.md)；不由定时器自动执行，不重复虚构审批。

## CI与本地检查

项目自行约定自动CI、手工CI、合并前本地检查或组合；本模板不默认生成CI配置，也不继承来源项目的CI暂停决定。本地通过不证明Runner通过，单测不替代数据库/浏览器，测试数量随项目变化不写死。
